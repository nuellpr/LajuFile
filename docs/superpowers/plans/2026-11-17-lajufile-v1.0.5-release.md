# LajuFile v1.0.5 Big Release Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Implement the `v1.0.5` reliability, security, proxy, video-audio, auto-update, Windows manifest/resource, and release-pipeline upgrades on `feat/hardening-polish` cleanly without bloating dependencies.

**Architecture:** Core storage/retry/network/crypto enhancements live in `lajufile-core` using existing `windows-sys`, `reqwest`, and pure-Rust `Sha256`. App-level `tools`, `installer`, `engine`, `app`, and `ui` consume those guarantees cleanly while `build.rs` + GitHub workflows keep version metadata and packaged assets synchronized automatically.

**Tech Stack:** Rust 2024 (`egui`/`eframe`, `tokio`, `reqwest`, `rusqlite`, `windows-sys`), Node MV3 tests, PowerShell/Bash installer & CI workflows.

**Spec:** `D:\LajuFile\docs\superpowers\specs\2026-11-17-lajufile-v1.0.5-release-design.md`

## Global Constraints
- Release version target is `1.0.5` across `Cargo.toml`, `extension/manifest.json`, `README.md`, and `lajufile.rc` (injected by `build.rs`).
- Zero new Cargo crate dependencies; use workspace crates and stdlib/OS APIs.
- Maintain existing security invariants (no overwrite on `finalize_temp`, fail-closed SSRF & bridge auth, DPAPI on Windows).
- Do NOT push, tag, or merge to `main` (keep changes cleanly committed on `feat/hardening-polish`).

## Review Focus
1. Cross-filesystem or exFAT/FAT32 finalization where `hard_link` fails with `Unsupported` / `INVALID_FUNCTION` / `EXDEV` must still refuse overwriting an existing `final_path`.
2. Insufficient disk space must reject allocation before `file.set_len(spec.size)` truncates or fills a drive, while resumed downloads must compare remaining bytes (`size - done`), not full size.
3. Invalid `proxy_url` in settings must produce a clear validation/status error rather than panicking or silently dropping auth/traffic; changing `proxy_url` must take effect on the live engine client.
4. Selecting `Audio only (m4a)` (from YouTube overlay or desktop Add dialog) must produce a `.m4a` output without `.mp4` double-extension or `--merge-output-format mp4`.
5. Upstream checksum verification in `tools.rs` must fail before renaming/extracting if `SHA2-256SUMS` / `.sha256` disagrees, and malformed manifest lines must not skip valid entries.
